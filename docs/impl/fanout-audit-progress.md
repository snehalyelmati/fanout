### Status rules

- `Open`: observed issue/candidate, no disposition approved. Every entry initially has decision `pending`, implementation `not started`, validation `not run`, Standards review `not run`, and Spec review `not run`; these defaults remain authoritative unless its entry records an override.
- `Decision-ready`: alternatives and tradeoffs prepared, still awaiting user approval.
- `Approved`: user has selected a resolution; code still requires the subsequent scoped implementation-plan approval.
- `Implemented`: local change exists, not a claim that checks or review pass.
- `Verified`: acceptance checks and independent Standards/Spec reviews pass with recorded commands/results.
- `Retained` / `Deferred` / `Not substantiated`: explicit user-approved disposition and reason; never counted as a fix.
- Confirmation by inspection or an in-memory audit probe is evidence of a finding, not post-fix validation.

Each entry preserves its original proposal and explicit user decision. Approved decisions and the implementation plan were the specification for the September audit. Group owners identify the original analysis and implementation ownership, not current assignments. Priorities: P1 correctness or major workflow risk; P2 policy/efficiency; P3 low-risk cleanup or measurement. Confidence concerns the observed behavior; proposed savings remain unmeasured unless stated.
