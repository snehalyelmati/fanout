# Normalize candidates before patch capture

One required, empty-able, repository-level direct-argv command list belongs to the approved Project Execution Profile rather than plans, details, packets, or work contracts. After a successful worker or repair edit, the controller runs that exact profile list once in the disposable candidate worktree before patch capture, typed ownership checks, and the original task validation. Nonzero results are audited and may retain partial deterministic fixes; launch, interruption, audit, or repository-identity failures fail closed without consuming model-repair budget.

This boundary keeps formatting and other deterministic repository fixers out of semantic repair retries without teaching Fanout about languages, package managers, tools, or stderr patterns. Initial integrated final validation itself does not run normalizers; a final-repair candidate does, under the already-derived upstream write authority, before final validation remains authoritative over that candidate.

Profile identity is bound into the packet and runtime evidence. Replacement uses `/fanout-plan --refresh-profile`; validation completes before pointer publication, and a failed refresh preserves the previous active profile. Normalizer scripts receive the controller process environment and declared command overrides, but not the worker subprocess's attempt/node variables.

Candidate normalizers that may rewrite tracked candidate files declare `expectedMutations: candidate-owned`. That phase-specific disclosure is invalid for preparation, readiness, and final gates; it grants no authority beyond the work contract, and clean-baseline profile validation must still remain Git-visible unchanged.
